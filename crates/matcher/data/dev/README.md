# DEVELOPMENT KEY ONLY — NOT A PRODUCTION KEY

`publisher.key` is the Ed25519 seed (hex) that signs `../matcher-data.signed.cbor` in development and CI. **It is public: it is in this repository.** Anything it signs proves nothing about where the data came from.

Rules:

- **Production keys never live in this repository, in CI secrets of this repository, or on a developer laptop.** They live in the release signing service, and the release build embeds their public halves through `TrustedKeys` in `src/signed.rs` with ids that are not `dev-*`.
- A production build **must not** trust `dev-2026-10`. The id prefix `dev-` is the tell; the release checklist greps for it.
- Rotating the dev key: write a new seed to `publisher.key`, run `cargo run -p lockdown-matcher --example sign-data`, commit the new `publisher.pub`, the re-signed file, and the new id in `TrustedKeys::dev()`.
- Never reuse this seed for anything else, and never copy it anywhere that is not this directory.

Files:

| File | What |
|---|---|
| `publisher.key` | 32-byte Ed25519 seed, lowercase hex, one line. Dev only. |
| `publisher.pub` | The matching 32-byte public key, lowercase hex. Embedded in the matcher as `dev-2026-10`. Generated by the example from the seed; do not hand-edit. |

See `docs/plan/09-extension-boundary.md` §2 and §5 (decisions proposed) for the policy.
